## 4. BUG 1 — WRITES FAIL AND THEN SILENTLY REVERT

Observed: assigning Maa Misra to slot 12–14 Sep showed a persistent "Couldn't save
change" banner, Retry did nothing, the banner kept reappearing, and the assignment
undid itself.

**CR-14.** **Never roll back an optimistic coordinator write.** v1 Section 12 says
this and the build does the opposite. A failed write stays on screen and stays queued.
Reverting is the worst possible behaviour here: it means the coordinator believes
something is recorded, looks away, and finds it gone.

**CR-15.** Persist the write queue to `localStorage` so it survives a reload and a
cold start.

**CR-16.** One persistent, quiet status bar — not a repeating snackbar. Text:
"Offline — {n} changes waiting". Retry is manual, plus automatic on regaining focus
and on `online`.

**CR-17.** Retry must actually retry. If Retry currently re-dispatches a request that
was never correctly formed, it will fail forever. Fix the request, not the banner.

**CR-18.** Most likely root cause, to check first: Apps Script Web Apps reject
cross-origin `POST` requests that trigger a CORS preflight, and they answer with a 302
to `script.googleusercontent.com`. A `fetch` with `Content-Type: application/json`
sends a preflight and fails. The fix:

```js
await fetch(WEB_APP_URL, {
  method: "POST",
  headers: { "Content-Type": "text/plain;charset=utf-8" },  // no preflight
  body: JSON.stringify(payload),                            // still JSON in the body
  redirect: "follow",
});
```

Plus: deploy with "Execute as: me" and "Who has access: Anyone", re-deploy as a **new
version** after every script edit (the old URL serves stale code otherwise), and parse
with `JSON.parse(e.postData.contents)` in `doPost`.

**CR-19.** Log the actual failure — status code, response text, whether the request
even reached the server — to the console, and surface it behind a long-press on the
status bar. Right now the failure is invisible, which is why it can't be fixed.

**CR-20.** Acceptance: assign a person, kill the network, assign another, reload the
page, restore the network. Both assignments must still be on screen throughout and
both must land in the sheet.

## 18. DESIGN SYSTEM

The app goes dark, warm and lamplit. The reference is the interior of a shrine at
arati: near-black brick, a single vessel of light, rows of oil lamps receding into the
dark. Palette derived from the shrine photograph already shared. **Profound, not
theatrical.** The fire is the light source, not the decoration — one accent, used
where meaning lives, and everything else quiet.

### 18.1 Principle

Colour is spent on state and nothing else. No gradient meshes, no glow on decoration,
no flame imagery as ornament. A screen at rest should look almost monochrome, and the
one card that needs attention should be the only warm thing in view.

### 18.2 Surfaces and text

```css
--bg:          #0E0B0A;  /* app background, warm near-black */
--surface-1:   #171211;  /* cards, nav bar */
--surface-2:   #1F1917;  /* expanded panels, sheets */
--surface-3:   #2A2220;  /* pressed state */
--hairline:    #2E2523;  /* 1px dividers */
--hairline-2:  #3A2F2B;  /* the heavier divider between panel groups */

--text-1:      #F5EDE6;  /* names, titles, primary */
--text-2:      #B8A9A0;  /* dates, secondary */
--text-3:      #7C6E68;  /* labels, inactive, TBD */
```

**CR-65.** Never pure black and never pure white. Every neutral carries the warm bias
above, so the dark reads as brick and lamp-shadow rather than as an OLED void.

### 18.3 Accent

```css
--ember:       #FF6A2A;  /* the single accent: active tab, chevron, focus ring */
--ember-dim:   #C4451F;
--ember-glow:  rgba(255,106,42,0.16);
--gold:        #E9A73C;  /* lit toggles only */
```

**CR-66.** One accent. The active tab, the focus ring, the chevron, the caret and the
primary CTA all use `--ember`. Nothing else in the app is allowed to be ember.

### 18.4 Slot state ramp — replaces v1 Section 15

The six states become a heat progression: unlit, then warming, then fully alight, then
settled. The current build's problem, visible in the schedule screenshot, is that TBD
and Missed are both red and read as relatives. They are opposites and must look it.

| State | Fill | Text on it | Reads as |
|---|---|---|---|
| TBD | `#221A18` | `--text-3`, name "TBD" | unlit, cold, empty |
| Assigned | `#3E2113` | `#F0D9CB` | first ember |
| Confirmed | `#5E2F0F` | `#FBE3CE` | catching |
| Kit collected | `#7E4A10` | `#FFEFD6` | burning |
| Done | `#2C5B3E` | `#D8EFDF` | complete, settled |
| Missed | `#8E1B12` | `#FFDCD6` | failure, unmistakable |

**CR-67.** TBD is **cold**, not red. It is an unlit lamp. This frees red entirely for
Missed, which is the one state that should make the coordinator's stomach drop.
`[OP-100]`

**CR-68.** Done breaks the warm ramp deliberately. Four consecutive warm steps are
already near the limit of glanceable distinction; a fifth warm terminal state would be
unreadable, and green is the one hue that reads as *finished* rather than *hotter*.
`[OP-101]`

**CR-69.** Every text colour above must clear 4.5:1 against its fill. Verify, don't
assume.

**CR-70.** Active slot stroke: 2px inset `--ember`, plus a 1px outer `--ember-glow`
halo. On a TBD card this is the only warm thing on screen, which is correct — that slot
is running now and has nobody in it.

**CR-71.** Completed batch: whole batch to 40% opacity, tick in the header in
`--text-3`. On dark, 45% was tuned for light mode and will still read as active.
